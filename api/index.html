    API reference

    Reading and saving

    Read CosMx AtoMx flat-file exports into SpatialData, in AtoMx global pixels.

    An AtoMx export folder (<inputs>) is expected to look like::

    <inputs>/
  flatFiles/<id>_metadata_file.csv[.gz]
  flatFiles/<id>_exprMat_file.csv[.gz]
  flatFiles/<id>-polygons.csv[.gz]
  flatFiles/<id>_tx_file.csv[.gz]
  CellComposite/CellComposite_F00001.jpg ...
  CellLabels/CellLabels_F00001.tif ...
  Morphology2D/*_F00001.TIF ...              (optional)

    where <id> is the dataset id (usually the slide name). :func:build_sdata turns it into one SpatialData object with these elements, all in the "global" coordinate system:

    ===================== ============================================================================== table counts (sparse int32) and cell metadata; cells named by cell (c_<slide>_<fov>_<id>) cell_boundaries one polygon per cell transcripts lazy points from a Parquet cache (x, y, z_raw, target, cell, CellComp, fov) fov<N>_image CellComposite of each FOV (lazy) fov<N>_labels CellLabels mask of each FOV (lazy) fov<N>_morphology Morphology2D of each FOV, one channel per marker (optional, lazy) ===================== ==============================================================================

    Each FOV is placed with x_global = x_local + dx and y_global = cy - y_local (image row = y_local).

    Speed: gzip is decompressed by pigz in a separate process when it is installed, CSVs are parsed by multithreaded pyarrow, transcripts are streamed to Parquet once (reused while newer than the CSV) and read lazily, and table, polygons and transcripts are read in parallel.

    load_slides(slides, input_dir, zarr_dir, cache_dir, *, rebuild=False, morphology=False)

    Open several slides, building the missing ones.

    Each slide is reopened from <zarr_dir>/<slide>_flat.zarr. A slide without a zarr is first built from <input_dir>/<slide>_inputs with :func:build_sdata and saved there.

    Parameters:

    Name Type Description Default
    slides

    Slide names, also used as the flat files' dataset ids.

    		 required
    input_dir

    Folder holding the <slide>_inputs export folders.

    		 required
    zarr_dir

    Folder of the <slide>_flat.zarr files.

    		 required
    cache_dir

    Transcript Parquet cache, as in :func:build_sdata.

    		 required
    rebuild

    True rebuilds every slide; a list rebuilds only those.

    		 False
    morphology

    Passed to :func:build_sdata.

    		 False

    Returns:

    Type Description
    dict

    {slide: SpatialData}. Images and masks are read lazily from the zarr.
    Notes

    ome_zarr's "no parent found" warnings (one per FOV mask, harmless) are silenced.

    save_table(sdata, table='table')

    Write sdata's table back into the zarr it was read from (e.g. after adding obs columns).

    spatialdata does not overwrite an element of its own backing zarr, so the table is deleted on disk and written again; images, masks, polygons and transcripts on disk are left unchanged. Takes seconds per slide. Do not interrupt it: between the two steps the zarr has no table.

    add_slide_view(sdata, name='slide')

    Add a coordinate system name: "global" mirrored in y (y = y_max - y_global).

    spatialdata-plot draws y downwards (the image convention); in this system plots show y upwards, as in the AtoMx slide view. "global" itself is left unchanged. Modifies sdata in place and returns it.

    Cores

    Cores of a TMA slide: their bounding box and a stitched, napari-ready SpatialData per core or slide.

    Two kinds of objects are supported everywhere:

    • a single slide (e.g. one value of :func:frzspatial.load_slides): unsuffixed elements (fov<N>_image, cell_boundaries, transcripts) in the coordinate system "global";
    • a merged object (several slides concatenated with spatialdata.concatenate): each slide's elements suffixed -<slide> and in their own coordinate system "global-<slide>", so slides never overlap.

    coordinate_system(sdata, slide)

    ("-<slide>", "global-<slide>") for a merged object, ("", "global") for a single slide.

    core_box(sdata, core, core_key='core_str', table='table')

    Bounding-box query arguments for one core of a single slide: the rectangle around its cells.

    Use as sdata.query.bounding_box(**core_box(sdata, "C4R7")).

    Raises:

    Type Description
    ValueError

    If no cell has obs[core_key] == core.

    build_core(sdata, slide, core=None, table='table', colors=None, scale_factors=(2, 2, 2), downsample=None, core_key='core_str', slide_key='slide')

    One core, or a whole slide, as a small SpatialData object for napari.

    The core's FOVs are stitched into one composite and one mask layer. FOVs are placed by their AtoMx offsets (x = col + dx, y = cy - row) in integer px, so stitching needs no resampling.

    Parameters:

    Name Type Description Default
    sdata

    A single slide or a merged object (see the module docs).

    		 required
    slide

    Slide name: selects the elements and coordinate system of a merged object, and the cells with obs[slide_key] == slide.

    		 required
    core

    Core name (obs[core_key]), or None for the whole slide.

    		 None
    table

    Table element name.

    		 'table'
    colors

    {column: {category: colour}}, stored as the table's <column>_colors: napari-spatialdata only colours a categorical column reliably with them.

    		 None
    scale_factors

    Pyramid of the image and masks: each level halves.

    		 (2, 2, 2)
    downsample

    Keep every n-th pixel of each FOV (the transformation scales it back to the slide's px). Default 1 for a core and 8 for a whole slide (a full-resolution slide is ~40 GB of RGB).

    		 None
    core_key

    obs columns of the core and slide names (slide_key is only used for a merged object).

    		 'core_str'
    slide_key

    obs columns of the core and slide names (slide_key is only used for a merged object).

    		 'core_str'

    Returns:

    Type Description
    SpatialData

    core_image (multiscale RGB), core_labels (each cell's mask value = its integer id in the table and polygons), cell_boundaries, transcripts and table (only cells with a polygon, as napari needs one shape per row; unused categories dropped; the original names in obs["cell_name"]), in the slide's coordinate system. Needs obs["fov"] and obs["slide_ID"].

    Examples:

    >>> from frzspatial.viewer import open_napari
>>> open_napari(build_core(slides["MN2"], "MN2", "C4R7"))

    Annotations

    Hand annotations: polygons saved as GeoJSON, turned into a cell-level obs column.

    Annotations are stored one file per core in an annotation folder, named <slide>_<core>.geojson (<slide>_slide.geojson for shapes drawn on a whole slide), with one class property per polygon and coordinates in the slide's global px. They are drawn with :func:frzspatial.viewer.annotate_core, but any GeoJSON in that layout works (e.g. exported from QuPath after converting to global px).

    This module does not need napari.

    annotation_file(annot_dir, slide, core=None)

    Path of a core's annotation file: <annot_dir>/<slide>_<core>.geojson (core None: <slide>_slide).

    read_annotations(path)

    Polygons of one annotation file as a GeoDataFrame (class, geometry), one row per polygon.

    A missing file gives an empty GeoDataFrame; multipolygons are split into polygons.

    write_annotations(annot, path)

    Save polygons (GeoDataFrame with class and geometry) to path; an empty one deletes the file.

    annotations_to_obs(sdata, classes, annot_dir='results/annotations', column='manual_annotation', table='table', slide_key='slide', core_key='core_str')

    Label each cell with the class of the annotated polygon around its centroid.

    Every <slide>_<core>.geojson in annot_dir is applied to the cells with obs[slide_key] == slide and obs[core_key] == core (all cells of the slide for <slide>_slide.geojson). Files of slides or cores not in the table are skipped, so the same folder can serve each slide and a merged object.

    Parameters:

    Name Type Description Default
    sdata

    A single slide or a merged object.

    		 required
    classes

    Class names in priority order: where polygons overlap, the class later in the list wins.

    		 required
    annot_dir

    Folder of the GeoJSON files.

    		 'results/annotations'
    column

    obs column to write.

    		 'manual_annotation'
    table

    Table element and its obs columns of slide and core names. Positions are CenterX/Y_global_px.

    		 'table'
    slide_key

    Table element and its obs columns of slide and core names. Positions are CenterX/Y_global_px.

    		 'table'
    core_key

    Table element and its obs columns of slide and core names. Positions are CenterX/Y_global_px.

    		 'table'

    Returns:

    Type Description
    Series

    Cells per class. obs[column] is set in place: categorical with every class as a category (used or not, so that tables annotated separately still share them when merged), NA outside every polygon.

    Examples:

    >>> annotations_to_obs(slides["MN2"], ["Glomerulus", "Artery"])
Glomerulus    126
Artery          0

    QC

    Per-cell QC of a SpatialData table.

    compute_sbr(sdata, bandwidth=0.01, weight_cutoff=0.08, bg_quantile=0.01, sbr_min=0, sbr_max=None, table='table', label='')

    Regional signal-to-background ratio (SBR) of each cell.

    Mean gene counts over mean negative-probe counts, each smoothed over the cell's neighbours with Gaussian weights. Same algorithm and defaults as computeSBR() in Barisano's CosMx QC (R).

    Parameters:

    Name Type Description Default
    sdata

    A SpatialData object whose table has CenterX/Y_global_px and probes named Negative* (negative probes) and SystemControl* (excluded).

    		 required
    bandwidth

    Gaussian bandwidth, mm.

    		 0.01
    weight_cutoff

    Neighbours with a smaller weight are ignored (sets the search radius).

    		 0.08
    bg_quantile

    The smoothed background is floored at this quantile of its positive values: a near-zero background otherwise gives ratios of ~1e9.

    		 0.01
    sbr_min

    Bounds on log2(SBR) for flag_sbr; None disables a bound.

    		 0
    sbr_max

    Bounds on log2(SBR) for flag_sbr; None disables a bound.

    		 0
    table

    Table element name.

    		 'table'
    label

    Prefix of the printed summary (e.g. the slide name).

    		 ''

    Returns:

    Type Description
    ndarray

    SBR per cell. obs gets SBR, log2SBR and flag_sbr in place.

    napari

    napari windows: view a SpatialData object, and draw annotations on a core or slide.

    Importing this module loads Qt, so import it only where a window is opened.

    Notes

    When Python runs inside another program (R through reticulate, Jupyter), the napari window belongs to that program: close it with the window's own close button. Quitting with Cmd-Q quits the host application's Qt loop and can hang it, and force-quitting the window kills the host (e.g. the R session). Annotations are saved after every change, so a hang loses nothing.

    patch_anndata()

    Restore AnnData._get_X, removed in anndata 0.13 but still called by napari-spatialdata 0.7 (colour by gene). Called by :func:open_napari and :func:annotate_core; call it yourself before opening napari-spatialdata another way.

    open_napari(sdata)

    Show sdata in a napari-spatialdata window; returns when the window is closed.

    The window can open behind other windows (look for it with Cmd-Tab / Alt-Tab).

    Examples:

    >>> open_napari(build_core(slides["MN2"], "MN2", "C4R7"))

    annotate_core(sdata, slide, core, classes, annot_dir='results/annotations', column='manual_annotation', colors=None, table='table', downsample=None)

    Draw regions on a core (or a whole slide) in napari, one layer per class; label the cells on closing.

    The core is stitched by :func:frzspatial.build_core and opened with its composite, cell outlines (not for a whole slide: ~70k outlines are slow) and one Shapes layer annot: <class> per class, holding this core's saved polygons. Draw polygons (P) or rectangles (R) in the layer of a class; ellipses are ignored. Each change is saved to <annot_dir>/<slide>_<core>.geojson (global px). When the window is closed, obs[column] is rebuilt from every saved file (:func:frzspatial.annotations_to_obs).

    		 required

    		 required
    classes

    Class names, in priority order for overlaps; classes found only in the saved file are added.

    		 required
    annot_dir

    As in :func:frzspatial.annotations_to_obs.

    		 'results/annotations'
    column

    As in :func:frzspatial.annotations_to_obs.

    		 'results/annotations'
    table

    As in :func:frzspatial.annotations_to_obs.

    		 'results/annotations'
    colors

    As in :func:frzspatial.build_core.

    		 None
    downsample

    As in :func:frzspatial.build_core.

    		 None

    H&E registration

    Register a whole-slide H&E (Aperio SVS) onto the CosMx cells, from tissue shape alone.

    register_he(cells_px, he_overview, he_um_per_overview_px, px_um=PX_UM, grid_um=50, min_blob_mm2=0.05)

    Fit the CosMx → H&E transform from tissue shape alone.

    1. Tissue masks on a grid_um grid: the H&E by Otsu threshold, the cells by occupancy.
    2. Rigid search: the 8 right-angle rotations and flips, then a ±4° sweep, each with its best translation by FFT cross-correlation (pixel sizes are known, so the scale is fixed).
    3. Landmarks: each tissue blob (e.g. a TMA core) fully covered by cells is paired with its H&E blob; with at least 3 pairs, outliers are dropped and the affine is refitted on their centroids.

    Parameters:

    Name Type Description Default
    cells_px

    (n, 2) cell centroids in global px.

    		 required
    he_overview

    A coarse H&E level, (y, x, 3).

    		 required
    he_um_per_overview_px

    µm per pixel of he_overview.

    		 required
    px_um

    µm per CosMx global px.

    		 PX_UM
    grid_um

    Mask grid, µm.

    		 50
    min_blob_mm2

    Smallest blob used as a landmark, mm².

    		 0.05

    Returns:

    Name Type Description
    affine Affine

    H&E µm → global px.
    pairs DataFrame

    Landmark pairs (x_px, y_px, he_x_um, he_y_um, resid_um).
    score float

    Fraction of the cells' tissue on H&E tissue.

    add_he_image(sdata, svs, name='he', px_um=PX_UM, grid_um=50)

    Add a whole-slide H&E (Aperio SVS) as a lazy multiscale image, registered onto the cells.

    The SVS's own pyramid levels become the scales, so nothing is read until plotted or written, except the coarsest level, used by :func:register_he. The pixel size comes from the SVS header (MPP). Landmark pairs are kept as shapes <name>_landmarks (H&E) and cell_landmarks.

    Parameters:

    Name Type Description Default
    sdata

    A single slide, e.g. from :func:frzspatial.build_sdata. Modified in place and returned.

    		 required
    svs

    Path of the SVS file.

    		 required
    name

    Image element name.

    		 'he'
